## App changes

Before this version, a transcript row's action bar copied that one row and nothing else.

- **Touch and hold a row** (right-click on Mac) for Copy, Select Text, Select Passages
  and Share. The tap action bar gains Select.
- **Select Passages** turns taps into checkmarks. The row menu adds Select Up to Here,
  which fills in every row back to the nearest picked one, and Select Whole Paragraph.
  A bar replaces the transport while selecting: Done, the count, Select Text, Copy and
  Share. The transcript options menu also starts selection. Following the audio pauses
  while picking, so rows do not scroll away under the finger.
- **Drag a row** into another app. A picked row carries the whole selection.
- **Select Text** opens the chosen rows in a read-only `UITextView`. It offers native
  word selection, Look Up, Translate and drag-out, plus Copy All and Share.
- Copied text rejoins rows the way the source paragraph reads: sentence rows of one
  paragraph keep their space or line break, and separate passages get a blank line.
  Shared text keeps the "— Osho, Series #N" attribution.
- `MARKETING_VERSION` 1.16.2, build 32.

A long press on a row that is both draggable and has a context menu leaves XCTest
waiting about 60 s for an animations-complete notification, before and after the menu.
During that wait the app process measured 0.0% CPU, with no idle wakeups and no power
draw, so it is a test-harness wait, not work on the device. Removing the drag modifier
removes the wait, and `.onDrag` behaves like `.draggable`. The UI tests keep long presses
to the two menu checks and start selection from the options menu or a launch argument.

As in other iOS apps, a finger that slides from a lifted row onto its menu picks a menu
item instead of dragging. The menu opens above a row low on the screen and from the
leading edge on iPad. The drag tests therefore start near the top and run down the
trailing side.
